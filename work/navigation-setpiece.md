# Veteran Cut — 6×6 항해 세트피스 설계

## 결론

현재의 장소 선택형 이동에 하루 한 번의 **저작된 항해 퍼즐**을 넣는다. 7개 레벨은 6×6 한 화면 안에서 끝나며, 무작위·실시간 압박·정밀 조작 없이 `암초 → 신호 → 조류 → 스위치/문 → 구조 → 이동 제한 → 종합` 순으로 규칙을 누적한다.

- 저작 목표 플레이타임: **30~38분**(브리핑, 고유 신호 문장, 구조 대화, 디브리핑 포함)
- 기계 퍼즐만의 숙련자 예상: **15~25분**; 하루 3~7분은 고유 서사 비트까지 구현했을 때 검증할 목표다.
- 최단 조타 수: **10 → 14 → 15 → 17 → 18 → 22 → 24**로 단조 증가
- 1~4일차 제한은 숙련 목표(soft), 5~7일차는 실제 계획 예산(hard)
- 모든 레벨은 BFS로 완주 가능성과 최단 경로를 검증했다.

100개 이상의 인디 게임을 해 본 플레이어에게 중요한 것은 복잡한 규칙 수보다 **새 규칙이 이전 규칙과 어떤 새 판단을 만드는가**다. 이 설계에서 조류는 단순 이동 보너스가 아니라 문을 넘는 수단이 되고, 구조자는 단순 수집물이 아니라 최적 경로의 순서를 바꾸며, 이동 제한은 처음부터 내세우지 않고 플레이어가 규칙을 충분히 배운 5일차부터 적용된다.

## 한 턴의 정확한 규칙

좌표는 `(x,y)`, 좌상단이 `(0,0)`, 우하단이 `(5,5)`다. 입력은 상·우·하·좌 네 방향뿐이다.

1. 플레이어가 인접 칸 하나를 고른다. 이 명령만 조타 1회를 소비한다.
2. 경계, 암초, 닫힌 문이면 명령은 실행되지 않고 조타도 소비하지 않는다.
3. 들어간 칸의 신호·생존자·스위치를 처리한다.
4. 조류 칸이면 화살표 방향으로 자동 한 칸 이동한다. 자동 이동은 조타를 소비하지 않는다.
5. 조류가 연속되면 차례로 처리한다. 밀릴 목적지가 불법이면 최초 명령 전체를 거부한다.
6. 목표 칸은 언제든 밟을 수 있지만 모든 신호 수집, 모든 생존자 구조, 모든 스위치 활성화 전에는 완료되지 않는다. 목표 테두리에 남은 조건 수를 표시한다.

스위치는 한 번 밟으면 영구 활성화된다. 문은 연결된 스위치가 켜지기 전에는 통과할 수 없다. 구조와 신호 회수는 되돌릴 수 없지만, **되돌리기 자체는 전체 상태 스냅샷을 복원**하므로 플레이어가 실험 때문에 손해 보지 않는다.

## 난도와 시간 곡선

| 일차 | 새 판단 | 목표 시간 | BFS 최단 | 제한 | 여유 |
|---|---|---:|---:|---:|---:|
| 1 | 암초를 읽고 두 신호를 한 항로로 잇기 | 3~4분 | 10 | 15 soft | +5 |
| 2 | 조류의 강제 착지점을 미리 읽기 | 3~4분 | 14 | 18 soft | +4 |
| 3 | 먼저 스위치를 밟고 문으로 복귀하기 | 4~5분 | 15 | 19 soft | +4 |
| 4 | 구조 우회와 신호 순서를 함께 최적화 | 4~5분 | 17 | 21 soft | +4 |
| 5 | 이미 배운 규칙을 22회 안에 실행 | 5~6분 | 18 | 22 hard | +4 |
| 6 | 두 스위치·두 구조자의 선후관계 | 5~7분 | 22 | 25 hard | +3 |
| 7 | 잠긴 해협 뒤 열린 바다의 순서를 최적화 | 6~7분 | 24 | 28 hard | +4 |

시간 목표는 강제 대기시간이 아니라, 플레이어가 직접 넘기는 1~2문장의 신호 기억과 구조 대화를 포함한다. 신호 문장은 서로 다른 인물·사건의 정보를 줘야 하며 같은 분위기 문장을 반복해 시간을 늘리면 안 된다. 6×6 보드만 놓고 보면 숙련자는 하루 1~4분, 전체 15~25분에 끝낼 가능성이 높다. 실제 블라인드 테스트에서 서사를 포함한 중앙값이 목표보다 20% 이상 짧으면 애니메이션을 늦추지 말고 고유 판단이나 필수 경로를 재설계한다.

## 레벨 명세

아래 해답의 `U/R/D/L`은 플레이어가 누르는 명령만 적는다. 조류가 만드는 자동 이동은 문자열에 포함하지 않는다. 정확한 ID와 기계 판독용 데이터는 `navigation-levels.json`에 있다.

### 1일차 — 첫 불빛

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,4) (2,3) (2,2) (4,4) (4,3) (4,2)`
- 신호: `(1,4) (4,1)`
- 조류/스위치/문/생존자: 없음
- 제한: 15회 soft
- BFS 최단: 10회, `URUUURRRUR`
- 의도: 목표를 향해 곧장 가는 것보다 왼쪽 신호를 먼저 챙기는 편이 자연스럽다는 것을 가르친다. 실패 조건 없이 조작과 목표 잠금을 익힌다.

### 2일차 — 바다가 미는 방향

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(1,0..4)`, `(3,1..4)`
- 신호: `(2,5) (2,2) (4,0) (5,3)`
- 조류: `(1,5)→R`, `(3,0)→R`
- 스위치/문/생존자: 없음
- 제한: 18회 soft
- BFS 최단: 14회, `RUUUUURRDDDUUU`
- 의도: 첫 조류는 안전한 튜토리얼이자 서쪽 암초벽을 넘는 유일한 입구다. 두 번째 조류 뒤에는 목표를 지나 남쪽 신호를 회수했다 돌아와야 하므로 “목표에 먼저 닿는 것 ≠ 완료”를 확인한다.

### 3일차 — 잠긴 항로

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,1..4)`, `(4,1..5)`
- 신호: `(1,4) (1,1) (0,3) (3,0) (3,5)`
- 조류: `(2,0)→R`
- 스위치: `west-bell(1,1)`
- 문: `bronze-gate(4,0)` ← west-bell
- 생존자: 없음
- 제한: 19회 soft
- BFS 최단: 15회, `RRRLLUULUURURRR`
- 의도: 남쪽의 편지를 먼저 건지고 서쪽 종으로 되돌아와야 한다. 스위치를 무시하고 위쪽 조류를 타면 문 앞에서 막히지만, 불법 조류 진입은 조타를 쓰지 않으므로 벌이 아닌 정보가 된다.

### 4일차 — 한 사람의 무게

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,0..4)`, `(4,0..2)`
- 신호: `(2,5) (3,3) (3,1) (5,2)`
- 조류: `(1,5)→R`
- 스위치: `rescue-lamp(5,3)`
- 문: `north-gate(5,1)` ← rescue-lamp
- 생존자: `rowan(5,5)`
- 제한: 21회 soft
- BFS 최단: 17회, `RRUUUUDDRRDDUUUUU`
- 의도: 위쪽 신호를 조사한 뒤 구조등과 표류자를 함께 처리하는 U자형 항로다. 구조자는 목표 조건이면서 별도의 짧은 대화를 제공해 수집 아이콘처럼 느껴지지 않게 한다.

### 5일차 — 남은 연료

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,5) (2,4) (2,2) (2,1) (4,4) (4,3) (4,1) (4,0)`
- 신호: `(0,3) (1,2) (3,3) (5,2)`
- 조류: `(0,4)→U`, `(3,2)→R`
- 스위치: `fuel-valve(1,0)`
- 문: `fuel-gate(5,1)` ← fuel-valve
- 생존자: `mara(3,5)`
- 제한: **22회 hard**
- BFS 최단: 18회, `UUUURDDDRRDDUUURUU`
- 의도: 처음으로 조타 예산이 실제 제약이 된다. 최단보다 4회 여유가 있어 첫 블라인드 시도에서도 한 번의 작은 경로 수정은 허용한다. 두 조류와 문을 최단 경로가 모두 사용하며, 4일 동안 이미 본 규칙만 조합하고 새 아이콘은 추가하지 않는다.

### 6일차 — 두 개의 약속

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,0) (2,1) (2,3) (2,4) (2,5) (3,0) (4,0)`
- 신호: `(1,4) (0,1) (3,4) (4,2)`
- 조류: `(1,2)→R`, `(3,2)→R`
- 스위치: `west-bell(0,0)`, `east-lamp(5,4)`
- 문: `strait-gate(2,2)` ← west-bell, `lighthouse-gate(5,1)` ← east-lamp
- 생존자: `sena(1,5)`, `tomas(5,5)`
- 제한: **25회 hard**
- BFS 최단: 22회, `RUULUUURDDRDDLRRDUUUUU`
- 의도: 서쪽 구역을 끝내고 해협을 연 다음, 동쪽에서 구조자와 등불을 처리해야 한다. 두 문은 각 구역의 진행 상태를 공간적으로 보여 주며 단순히 스위치 수만 두 배로 늘리지 않는다.

### 7일차 — 일곱 번째 새벽

- 시작/목표: `S(0,5)`, `G(5,0)`
- 암초: `(2,0) (2,1) (2,2) (2,3) (2,5)`, `(4,0)`
- 신호: `(1,2) (0,2) (1,0) (3,3) (4,2) (5,3)`
- 조류: `(1,4)→R`, `(3,4)→R`
- 스위치: `memory-bell(0,0)`, `keeper-lens(3,5)`
- 문: `memory-gate(2,4)` ← memory-bell, `lens-gate(5,1)` ← keeper-lens
- 생존자: `rowan(0,4)`, `mira(3,5)`, `ion(5,5)`
- 제한: **28회 hard**
- BFS 최단: 24회, `UUUUURDDDDRDLRRUULLURURU`
- 의도: 왼쪽의 기억문은 조류로만 넘지만, 문 뒤 바다는 다시 3열 폭으로 열려 신호와 두 생존자의 순서를 계획할 수 있다. 최단 해답도 4개라 단일 복도를 암기하는 시험이 아니며, 두 조류와 두 문은 모든 최단 해답에서 실제 사용된다. 마지막 렌즈문은 목표 바로 아래에 있어 배운 규칙을 건너뛸 수 없다.

## 구현용 상태와 처리 순서

`navigation-levels.json`은 브라우저 JS에서 그대로 `fetch`하거나 `game.js` 상수로 가져올 수 있는 형식이다. 최소 런타임 상태는 다음이면 충분하다.

```js
const navState = {
  levelId: 'nav-05',
  pos: [0, 5],
  signalMask: 0,
  survivorMask: 0,
  switchMask: 0,
  moves: 0,
  history: [] // 이동 전 전체 상태 스냅샷; undo용
};
```

권장 이동 처리 의사코드:

```js
function tryMove(dir) {
  if (hardLimitReached()) return announce('연료가 없습니다. 되돌리기를 사용하세요.');
  const before = structuredClone(navState);
  const first = add(navState.pos, DIR[dir]);
  if (blocked(first, navState.switchMask)) return bumpWithoutCost(first);

  enter(first); // signal, survivor, switch
  const seenCurrents = new Set();
  while (currentAt(navState.pos)) {
    if (seenCurrents.has(key(navState.pos))) return restore(before); // 데이터 오류 방어
    seenCurrents.add(key(navState.pos));
    const landing = add(navState.pos, DIR[currentAt(navState.pos).dir]);
    if (blocked(landing, navState.switchMask)) return restoreAndBump(before, landing);
    enter(landing);
  }
  navState.history.push(before);
  navState.moves += 1;
  autosaveNavigation();
  checkCompletion();
}
```

저장에는 현재 상태뿐 아니라 `history`도 포함해야 재실행 직후 되돌리기가 유지된다. 용량이 부담되면 최대 40개의 작은 스냅샷만 저장하면 된다. 완료 플래그는 `S.navigationDone[day] = true`처럼 기존 일차 저장에 합친다.

## 기존 게임 루프에 넣는 위치

그날의 등대가 해금되어 플레이어가 등대를 선택하는 순간 항해 세트피스를 시작하는 것이 가장 자연스럽다.

1. 그날 앞선 장소들의 기억을 확인한다.
2. 등대 아이콘을 선택한다.
3. 해당 일차 항해 레벨을 완료한다.
4. 기존 등대 장면 → 신호 퍼즐 → 잔상 → 추론 → 기억 잠수 순서를 계속한다.

완료한 항해는 다시 요구하지 않는다. 중간에 메뉴로 나가면 같은 칸·같은 회수 상태·같은 남은 조타에서 재개한다. 항해 신호 문장은 기존 `42 clues` 완주 조건에 추가하지 말고, 별도 `navigationEchoes`로 일지에 보관해야 기존 세이브/업적 조건을 깨지 않는다.

## 숙련자 UX 원칙

- **계획이 먼저 보이게:** 커서를 올리면 한 번의 입력과 조류 착지점까지 점선으로 미리 보여 준다. 닫힌 문으로 밀리는 경우 착지점에 자물쇠를 표시한다.
- **실험 비용 제거:** `Z`, 게임패드 `B`, 화면 버튼으로 무제한 되돌리기. 재시작은 즉시 가능하되 현재 시도만 초기화한다.
- **불법 이동은 연료를 쓰지 않음:** 암초나 닫힌 문을 확인한 것을 실패로 취급하지 않는다.
- **hard 제한의 공정성:** 남은 조타가 5/3/1회일 때만 단계적으로 알린다. 0회가 되면 실패 화면 대신 이동을 막고 되돌리기·재시작·도움받기를 제시한다.
- **도움 3단계:** 1) 아직 필요한 목표 강조, 2) 다음에 처리할 구역 강조, 3) 최대 3개의 입력만 화살표로 제시. 두 번 실패하면 hard 제한을 soft로 바꾸는 선택지를 제공한다.
- **정보를 숨기지 않음:** 암초, 조류 방향, 연결된 스위치-문은 시작부터 모두 보인다. 반전 스토리는 숨겨도 퍼즐 규칙은 숨기지 않는다.
- **빠른 재도전:** 신호 문장은 같은 시도에서 한 번 본 뒤에는 작은 토스트로 축약한다. 이미 읽은 대화를 재시작 때 강제 재생하지 않는다.

## 접근성 규칙

- 방향키/WASD, D-pad, 마우스/터치 모두 같은 한 칸 명령을 사용한다. 아날로그 정밀도와 빠른 반응을 요구하지 않는다.
- 조류·문·신호·생존자는 색뿐 아니라 `화살표/자물쇠/전파/구명환` 형태를 함께 쓴다.
- 고대비 모드에서는 타일 경계를 2px 이상으로 유지하고, 현재 위치와 목표를 서로 다른 패턴으로 표현한다.
- 감소된 모션에서는 밀림 애니메이션 대신 출발 칸 화살표 점멸 → 착지 칸 강조로 즉시 전환한다.
- 각 칸의 접근성 이름 예: `열 2, 행 5, 동쪽 조류, 미수집 신호, 이동 가능`. 이동 후에는 `동쪽 조류로 한 칸 밀림, 남은 조타 7`을 라이브 영역으로 알린다.
- 사운드는 분위기 보조만 하며 신호 수집·문 개방·조류 방향을 화면 정보 없이 전달하지 않는다.
- 시간 제한은 없다. 메뉴를 열거나 신호 문장을 읽는 동안 어떤 상태도 변하지 않는다.

## BFS 검증

검증 상태는 `(x, y, signalMask, survivorMask, switchMask)`이고, 간선 비용은 플레이어 명령 1회다. 조류 밀림은 같은 간선 내부에서 처리했다. 목표 조건은 목표 좌표 도달과 세 마스크의 완성이다. 따라서 BFS가 처음 찾은 경로가 조타 수 기준 최단이다.

실행:

```powershell
node work/validate-navigation.cjs
```

검증 결과:

```text
nav-01 optimal=10 limit=15 ways=4 currents=0/0 gates=0/0 URUUURRRUR
nav-02 optimal=14 limit=18 ways=4 currents=2/2 gates=0/0 RUUUUURRDDDUUU
nav-03 optimal=15 limit=19 ways=6 currents=1/1 gates=1/1 RRRLLUULUURURRR
nav-04 optimal=17 limit=21 ways=12 currents=1/1 gates=1/1 RRUUUUDDRRDDUUUUU
nav-05 optimal=18 limit=22 ways=4 currents=2/2 gates=1/1 UUUURDDDRRDDUUURUU
nav-06 optimal=22 limit=25 ways=36 currents=2/2 gates=2/2 RUULUUURDDRDDLRRDUUUUU
nav-07 optimal=24 limit=28 ways=4 currents=2/2 gates=2/2 UUUUURDDDDRDLRRUULLURURU
```

`ways`는 동일한 최단 조타 수로 완주하는 입력열 수다. `currents/gates`는 대표 최단 해답에서 실제 사용한 장치 수/배치 수다. 검증기는 좌표 범위, 암초 중첩, ID 중복, 문 연결, `limitMode`, JSON의 `verifiedOptimalMoves`와 `minimalSolution`, 제한 충족, 최단 경로의 모든 조류·문 사용을 함께 검사한다. 불일치 시 종료 코드 1을 반환하며 현재 종료 코드는 0이다. 최단 거리 증가는 작업량 곡선의 보조 지표일 뿐, 체감 난도는 아래 블라인드 테스트로 따로 판정한다.

## 블라인드 플레이테스트 합격선

구현 뒤에는 제작자가 아닌 5명 이상에게 무설명 첫 플레이를 맡긴다.

- 1~2일차 규칙 이해 성공률 90% 이상
- 5~7일차 도움 없이 완주 70% 이상, 도움 포함 100%
- 불법 이동의 원인을 3초 안에 이해 90% 이상
- “내가 계획해서 풀었다” 5점 척도 평균 4.0 이상
- “같은 퍼즐을 숫자만 바꿨다” 응답 20% 미만
- 기계 퍼즐만의 전체 중앙값 15~25분; 고유 서사 비트를 포함한 저작 목표 30~38분, 개별 3~7분
- 소프트락, 저장 후 상태 변경, 입력 손실 0건

숙련자에게 가장 치명적인 것은 어렵다는 사실이 아니라 **시간을 존중하지 않는다는 느낌**이다. 위 기준에서 시간이 짧으면 고유 판단을 추가하고, 시간이 길면 이동 애니메이션이 아니라 왕복 경로를 줄인다.
